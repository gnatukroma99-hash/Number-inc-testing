# ARCHITECTURE — «ЧИСЛО»

Правила: **движок не знает имён механик**, весь контент — данные, новая механика = папка + данные.
Горизонт планирования — **Ярус 1 (20 механик) + Ярус 2 (10 механик)**. Дальше не проектируем.

---

## 1. Принципы

1. **Данные отдельно от кода.** Формулы, цены, эффекты, барьеры — строки в `src/content/` и в `index.js` механики.
2. **Реестр вместо импортов.** `G.registry` собирает всё; движок обходит реестр.
3. **Никаких абсолютных потолков.** Всё, что «стена», — запись в `content/barriers.js` и снимается навсегда.
4. **Универсальный сброс.** У каждой сущности `scope: 'run' | 'tier' | 'meta'`. Списков «что обнулить» нет.
5. **Логика не знает про DOM.** Доска (`board.js`) — отдельный файл, общается через `G.h` и `update(state)`.
6. **Строгий BigNum.** Арифметика над `N` — только через `G.BN`.
7. **Классические скрипты, не ESM.** Игра обязана работать из `file://` без сервера (ESM там блокируется CORS).
   Каждый файл — IIFE, пишет в `window.G`.

## 3. Контракты

### 3.1 Механика (`mechanics/<id>/index.js`)

```js
G.registry.addMechanic({
  id: 'digitsum',        // уникальный, совпадает с папкой
  order: 1,              // порядок в списке доков
  name: 'Сумма цифр, брат',
  short: 'Цифры',        // подпись в доке
  icon: 'Σ',
  scope: 'run',          // что сбрасывать при престиже
  hint: 'текст-подсказка на доске',

  isUnlocked(state) {},  // необязательно; по умолчанию — всегда
  mult(state) {},        // множитель к M_total (number). Необязательно
  dtMult(state) {},      // множитель к ΔT (number, <1 = быстрее)
  speedBonus(state) {},  // прибавка к speedBonus (0.1 = +10%)
  tick(state, dt) {},    // своя логика раз в тик
  onReset(state) {},     // очистка приватных данных
  status(state) {}       // короткая строка для бейджа дока
});
```

### 3.2 Доска (`mechanics/<id>/board.js`)

```js
const mech = G.registry.mechanic('digitsum');
mech.board = {
  mount(rootEl) {
    // строится ОДИН раз
    return { update(state) { /* только текст/классы, без innerHTML */ } };
  }
};
```

### 3.3 Апгрейд (данные)

```js
G.registry.addUpgrade({
  id: 'sd', mech: 'digitsum',      // к какой доске относится
  name: 'Сумма цифр, брат',
  res: 'energy',                   // чем платим (id ресурса)
  base: 60, growth: 1.9, max: 20,  // цена = base · growth^lvl
  costFormula: null,               // альтернатива: своя строка-формула от lvl
  formula: '1 + 0.005 * S * lvl',  // ЭФФЕКТ (number), vars: lvl, D, S, q, z, d1, rho, prime, t
  fmt: 'x',                        // 'x' | 'pct' | 'num' — как показывать
  note: 'M ×= 1 + 0.005·S·lvl',    // настоящая формула мелким шрифтом
  scope: 'run',

  /* необязательные машинные эффекты (v0.2.0) */
  addM: '500 * lvl',        // прибавка к M_base
  powM: '1.05 ** lvl',      // степень бонуса механик (≤ 1.5)
  dtMult: '0.95 ** lvl',    // множитель ΔT
  energyMult: '2',          // множитель энергии

  /* альтернативная цена — В ЦИФРАХ (магазин «за число») */
  costD: '0.80 * 1.8 ** lvl', minD: 18,

  /* автоматизация: если куплен — доска сама покупает свои апгрейды */
  autoMech: 'digitsum', scope: 'meta',

  /* v0.4.0 */
  autoBuy: false,           // false = автоматизация НЕ покупает этот апгрейд сама
  Mmult: '1.6 ** lvl',      // плоский множитель к M_total (дерево ◆)
  spanMult: '1.12 ** lvl',  // ширина зоны невидимого софткапа ×
  requires: ['tree_tempo'], // предки-узлы (дерево): у каждого уровень > 0
  tier: 't1'                // ярус доски-дерева (для группировки в UI)
});

/* Дерево ◆: узлы — те же апгрейды, только платим ядрами. */
G.registry.addUpgrade({
  id: 'tree_auto_all', mech: 'tree', tier: 't2', scope: 'meta',
  res: 'cores', base: 25, growth: 1, max: 1, formula: 'lvl'
});
/* Право автопокупки авто-апгрейдов задаётся данными:
   G.content.automation.autoAllGate = 'tree_auto_all' — движок имён узлов не знает. */
```

## 4. Язык формул

`G.formula('1 + 0.005 * S * lvl', {...}) -> number`

Доступно: `+ - * / ** ( )`, `Math.*` (sin, cos, min, max, floor, sqrt…), плюс помощники:

| Функция | Смысл |
|---|---|
| `log10(x)` | десятичный логарифм |
| `clamp(x,a,b)` | ограничение |
| `lerp(a,b,t)` | линейная интерполяция |
| `taper(x, wall, width)` | затухание у барьера, возвращает 0..1 |

Переменные по умолчанию: `lvl`, `D`, `S`, `q`, `z`, `d1`, `rho`, `prime`, `t`.

> ⚠️ Степень — только `**` или `pow(a,b)`. Знак `^` в JS это XOR — не использовать.

## 5. Сброс по scope

```
run  — N, энергия, раундовые апгрейды, данные механик со scope:'run'
tier — валюта яруса (❖, ◆), дерево яруса
meta — Δ/Ψ/Ω, auto3, ачивки, разблокировки, настройки
```

`G.resetScopes(state, ['run'])` — П1. `G.resetScopes(state, ['run','tier'])` — переход яруса.

---

## 6. Как добавить механику (чек-лист)

1. `src/mechanics/<id>/index.js` — `addUpgrades([...])` + `addMechanic({...})`.
2. `src/mechanics/<id>/board.js` — `mech.board.mount`.
3. Добавить два `<script>` в `index.html` (index.js — до `ui/components.js`, board.js — после).
4. Ресурс (если нужен новый) — в `src/content/`.
5. Записать в `docs/MECHANICS.md`.
6. Запись в `docs/CHANGELOG.md`.
7. Проверить, что сброс по scope корректен и доска блокируется до `isUnlocked`.

**Ни один пункт не требует правок в `core/` и `systems/`.** Это и есть критерий масштабируемости.
